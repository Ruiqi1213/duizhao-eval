# 对照 · 文档 AI 评测台

面向 AI 产品经理的文档生成方案对比工具：同一任务、相同参考材料，两套候选输出先匿名评分，再统一揭晓结果。

## 项目速览

选择文档生成模型或 Prompt 时，“哪份看起来更好”很难支持复核。对照把两份候选输出放到同一任务和材料下：先按事实忠实度、要求完整度、结构可用性独立评分并记录依据，全部提交后才揭晓方案身份。首版先把人工评审流程做清楚，不把综合分直接当作上线结论。

**示例｜虚构材料，仅演示评分方法。** 任务是把一段内部通知改写成简明摘要。原文规定“提交后 2 个工作日内反馈”。候选 A 保留时限；候选 B 写成“当天反馈”。即使 B 更流畅，也应指出时限与原文不符，在事实忠实度上扣分，并引用原文让同事复核。A 也仍需检查是否覆盖其他任务要求。

**验证与体验。** [验证记录](docs/VALIDATION.md)记录了 2026-09-08 的规则测试、接口流程、类型检查与生产构建；没有真实用户或模型选型成效数据。仓库可按下文在本地体验，用内置虚构任务走完整流程；源码 ZIP 不是在线演示。更多见 [评测方法](docs/EVALUATION.md)和 [作品集讲述提纲](docs/PORTFOLIO.md)。

## 可以做什么

- 使用四个人工编写的中文示例任务，或导入自己的真实生成结果。
- 在创建评测时调整三个维度的评分锚点与权重，保存为本轮快照。
- 对两份候选输出独立打分，记录事实错误、遗漏、结构问题及对应依据。
- 完成全部任务后，比较质量、逐项胜出情况、生成耗时和成本。
- 导出 Markdown 报告和包含评分依据的 JSON 记录。
- 数据保存在服务端数据库中；刷新页面不丢失已提交评分。

**这不是自动模型排行榜。** 内置内容由人工编写，不是模型实测；首版不请求模型，也不提供 AI 自动打分。耗时和成本来自用户导入的记录，未由平台核验。匿名表示评分时隐藏方案名称与顺序映射，不保证输出内容本身无法被辨认。

## 三个产品取舍

1. **按场景定义质量，而非只给综合分。** 事实忠实度、要求完整度、结构可用性分别提供 1 / 3 / 5 分锚点；事实严重低分在报告中单独提示。
2. **先完成盲评，再揭晓方案。** 每个任务单独随机 A/B；映射保存在服务端，未完成整轮评分时接口不返回身份。身份揭晓前还隐藏成本和耗时，减少提示偏差。
3. **可追溯优先于随手改分。** 已提交评分不能覆盖；任务和标准锁定。需要更改标准、材料或重新评分时新建实验，保留原始记录。

## 体验路径

打开评测工作台 → 阅读参考材料 → 给 A、B 各打三项分数 → 填写问题依据 → 提交本组 → 完成四组 → 查看报告并导出。

只有分数选完才能提交；1 分项必须有至少 4 字说明。未经提交的表单修改不属于正式记录。

## 本地运行

环境：Node.js 22.13+（验证环境为 24），npm。公开仓库无需 `.openai/hosting.json`、账号或模型密钥即可使用本地 D1 预览。请只把开发服务绑定到本机。

**Windows PowerShell**：

```powershell
npm.cmd ci
$env:WRANGLER_WRITE_LOGS = 'false'
$env:WRANGLER_LOG_PATH = '.wrangler/logs'
npx.cmd wrangler d1 migrations apply DB --local --config wrangler.local.json
npm.cmd run dev -- --hostname 127.0.0.1
```

**macOS / Linux**：

```sh
npm ci
WRANGLER_WRITE_LOGS=false WRANGLER_LOG_PATH=.wrangler/logs npx wrangler d1 migrations apply DB --local --config wrangler.local.json
npm run dev -- --hostname 127.0.0.1
```

浏览器打开终端给出的本地地址。迁移已提交，无需重新生成。`--local` 只操作本机评测数据库，请勿改成 `--remote`。如遇端口占用，可加 `--port 3001` 并打开终端显示的对应地址。

- 规则自检：`node --test tests/domain.test.mjs`
- 类型检查：`npx tsc --noEmit`（PowerShell 可用 `npx.cmd tsc --noEmit`）
- 接口自检：保持开发服务运行，在第二个终端执行 `node tests/api.test.mjs`。默认端口是 3000，改过端口时通过 `EVAL_TEST_URL` 指向实际本地地址。脚本只允许本地地址，会创建标明“非真实评测”的本地测试实验，不改动内置示例评分。

**生产构建**：`npm run build` / `npm start` 仍用于已有 Sites 托管流程。构建需要平台生成的 `.openai/hosting.json`，公开仓库缺少该文件时会明确提示使用本地开发命令。请勿把托管配置提交到公开仓库。私有部署由 Sites 网关控制访问，首版是单工作区设计，**不能直接移除网关作为公开多人 SaaS 使用**。

## 目录

- app：主工作区及评测接口
- components：导入、评分、报告交互
- lib/eval.ts：输入校验、盲评映射、加权统计、报告导出
- db / drizzle：数据表与迁移
- tests：评分规则与接口工作流验证
- docs/PRD.md：产品定义、范围、验收与迭代
- docs/EVALUATION.md：指标口径与评测方法
- docs/PORTFOLIO.md：作品集讲述提纲

## 已知边界

- 单评审人、每轮两套方案、1—30 个任务；不支持多人一致性统计。
- 只有所有任务评分完成后才能导出报告；不可判断的样本应在建立正式实验前剔除或补充材料。
- 当前不支持 PDF/OCR、自动模型调用、自动评委、可视化标注定位或自动版本复测。
- 模型费用为人民币单次记录，不涉及汇率换算；不可将缺失值视为 0。
- 不上传内部机密、第三方隐私或未经授权的公司资料。
- WebMCP 做渐进增强；普通浏览器没有该能力时不影响页面使用，真实注册契约尚未在支持环境中验证。
