# 对照：产品需求文档 v0.1

状态：个人作品项目；基于明确的产品假设开发，尚未进行真实用户访谈。不是公司项目或已获验证的商业产品。

## 1. 用户与问题

目标用户是需要选择文档生成模型或 Prompt 版本的 AI 产品经理。一次生成“看起来不错”不足以支持方案选择：材料不同、标准模糊、模型品牌预期和缺失的调用记录都可能干扰判断。

本项目要验证的假设：让评审人使用同一组任务与评分锚点，并保留逐项依据，比仅凭印象比较两份输出更容易复盘选型理由。该假设尚未验证。

## 2. 首版目标与非目标

目标：一人能完成“准备任务—配置标准—匿名评分—对照分析—导出依据”的完整流程。

不做通用聊天、复杂工作流编排、海量模型榜单或自动宣称某个模型最好。首版接收已经生成好的输出；不接 API Key、不调用模型、不把人工示例包装成实测结果。

## 3. 核心需求与验收

| 模块     | 用户操作与规则                                | 验收                                                         |
| -------- | --------------------------------------------- | ------------------------------------------------------------ |
| 新建评测 | 选择示例或导入 JSON，填写名称，配置权重与锚点 | 1—30 个任务，恰好 2 个方案，权重合计 100                     |
| 任务样本 | 同一材料和要求对应两份候选输出                | 空材料、空输出、非法数值拒绝创建                             |
| 匿名评审 | 每题随机 A/B，三个维度分别评分                | 刷新后顺序不变；未完成整轮时接口无名称与映射                 |
| 问题记录 | 选择标签，补充问题依据                        | 有 1 分必须填写说明，不用“低分”代替原因                      |
| 评分提交 | 一次提交两份输出的六项分数                    | 原子写入；重复提交不覆盖，提示已有记录                       |
| 结果报告 | 还原方案归属，对比均分、单题结果和记录覆盖量  | 换位映射正确；同分并列；缺失指标不计为零                     |
| 导出     | 导出报告或完整评分记录                        | 包含任务、标准快照、原始输出、方案映射、评分、依据与结论边界 |

## 4. 主要产品决策

- 三档评分对应明确锚点，避免评审者凭直觉区分 2 分和 3 分。
- 整轮完成才揭晓身份，避免先完成的题目影响后续评分。
- 标准与已提交分数锁定，换来可追溯性；修改应创建新实验，首版不做审计日志和多版本合并。
- 演示结果无预填评分。用户必须自己判断，作品展示的是真实产品交互，不是静态排名看板。
- 事实严重低分单独提示，不能用结构好看、总分较高掩盖事实问题。
- 字符长度是确定性检查，只展示，不冒充语义质量评价。
- 耗时和费用来自导入记录，展示有效记录数，避免不同缺失率下误导比较。

## 5. 异常与边界

加载失败提供重试；导入失败保留输入并提示原因；低分无依据阻止提交；重复提交拒绝覆盖；评分未完成不解锁报告。正式提交前仍需由人确认判断是否有材料依据。

首版私有单人空间，不支持公开用户注册、角色权限及多人共享。公开之前需要身份隔离、配额、速率限制和安全审查。未提交的表单不是正式数据，不能承诺刷新后恢复。

## 6. 产品验证计划（尚未执行）

邀请 3—5 位有实际文档任务的同事试用。准备一次真实 Prompt 版本选择问题，不预设赢家。

观察：能否独立导入、能否理解锚点、哪些题无法评分、低分依据是否可复核、报告是否帮助决定下一步。

拟收集指标：有效实验完成率、每题评分用时、低分依据填写率、复评一致性、报告使用反馈。没有基线前不承诺提升幅度。

## 7. 迭代顺序

P0 已实现：导入、标准快照、匿名评分、服务端持久化、问题记录、报告导出。

P1 候选：真实用户试用；任务级“无法评估”及排除原因；多人复核；实验复制复测。

P2 候选：选定一个模型服务后接入生成调用，记录真实耗时和成本；引入 AI 初评时与人工分数分列，先验证一致性。并非所有候选都必须做。
