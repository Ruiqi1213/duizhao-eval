# 评测方法与指标口径

## 数据来源

内置四个任务及两组候选输出由人工编写，内容虚构，不使用公司文件。评分初始为空。导入任务的来源、模型名称、延时和费用由导入者提供，平台不保证其真实性。

评分不是模型自动判分。首版也不将自动字符串比对称为“AI 打分”。

## 评分规则

默认维度：事实忠实度 40%、要求完整度 35%、结构可用性 25%。每项仅可选 1、3、5 分。锚点随实验存储，不能在已有实验中调整。低分需填写问题说明。

第一维用于检查内容是否忠实于来源；第二维用于检查遗漏；第三维用于判断结构能否使用。避免把同一处遗漏同时算作事实错误。

每份输出的加权总分 = Σ（维度分数 × 维度权重 / 100）。
每套方案的平均分 = 已完成任务总分之和 / 已完成任务数。
胜出数以同任务两份输出的加权总分比较，并列独立计数。
事实低分项是第一维得 1 分的任务数量，提示人工复核，不作为独立事故判定。

首版固定三个维度的名称与顺序，允许修改权重和评分锚点。这样保持维度含义与报告风险提示的一致性。

## 耗时与费用

latencyMs 为每条生成结果的毫秒耗时；costCny 为该次调用的人民币费用。两者是导入数据，不是页面评分用时。

平均值只包含非 null 记录。0 是有效的已记录数值，null 表示缺失。每项附有效样本量；两方案数据覆盖不同或计费口径不同，不应直接做成本结论。

字数检查按 Unicode 码点计数，包含空白与标点。不是分词 Token 数，也不计入质量总分。

## 匿名与可复核

每个任务单独随机排列，排列保存在服务端。整轮未完成前，接口不返回方案名字、排列映射或调用指标。全部完成后记录中每份输出附方案名称，报告还原为一致的方案顺序。

这不能消除输出措辞带来的身份线索，也不意味着双盲研究。这里只有一名人工评审人，尚无多人一致性和统计显著性证明。

## 结论边界

评分只反映该任务集、参考材料与评审人的判断。报告可提出“下一轮复核哪些问题”，不自动做采购或生产发布决策。示例任务的结果不能用作真实模型排行。

评分无法完成时不应猜分。当前首版需在建实验前排除不适合评估的样本；带原因的排除机制列为后续候选。
